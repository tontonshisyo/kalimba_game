# Anonymous usage analytics

Client: assets/js/analytics.js. Server: deploy analytics-edge.ts as `usage`, verify_jwt=false (publishable API key checked by handler). Run analytics-schema.sql first. Database writes/RPC are service-role only. Admin dashboard uses an invoker RPC under authenticated RLS; non-admins cannot read events. Never put service credentials in frontend files.

Collection is active on the two production hostnames only. Local/offline builds do not collect. Privacy settings in policy.html allow opt-out; GPC/DNT disables collection. Anonymous browser UUID is in localStorage; tab UUID is in sessionStorage. Opt-out clears queued events and local identifiers. Previously received events age out normally. No message, title, chart content, URL/hash, email, full user agent or raw IP is saved in usage_events. The Edge Function uses a daily salted IP hash solely for ingestion limits.

Events cover visits, approximate visible minutes, orientation, coarse device/browser, selected control clicks/settings, game starts/finish/explicit exit/pause, mode, official catalog IDs or `custom`, BPM, note count, results, recording start/end, successful save, long/short share creation, successful copy/OS share, and shared-link opening success/failure. A click is an attempt, never represented as a success. Tab close or offline network loss may lose queued events and are not counted as explicit game exit. OS share resolution does not prove a social post was published. Edited chart trials and tutorial are separate modes. Page views include privacy-page views.

Queue: batches up to 20, max 60 queued, 20-second flush plus visibility/pagehide best effort. No blocking UI, infinite retries, raw per-key press events or offline upload backlog. Keepalive delivery remains best effort. Browser count is approximate (storage clearing, shared devices, tabs, blockers and opt-out affect results). Visible minutes is a 60-second estimate and omits short visits.

Retention: delete detailed events older than 180 days on ingestion; at 100,000 events remove oldest 5,000 before new batch. Maximum 2,000 received events per originating IP/day and roughly 1,000 per visitor/day. IDs deduplicate retries. Counts and cap checks are operational protection, not proof against determined fabricated traffic. There is no indefinite daily-history archive; expired/deleted detail no longer contributes to historical results. Dashboard displays rolling 7/30/90 Japan-calendar days, browser counts, tab counts, event/feature/mode/reason counts, song start/finish/exit and average results, environment, retained short-link totals. Export aggregated JSON from dashboard; it contains no browser identifiers.

No analytics is loaded on the admin page. All schema/setup files and Edge source are checked in for repeatable deployment; runtime secrets remain in Supabase.
